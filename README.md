## 项目定位

亿企工场 MES 是亿企工场的制造执行业务应用，目标是把生产标准、计划排程、现场任务、人员设备实绩、质量结果和物料批次串成可执行、可反馈、可追溯的生产闭环。

本仓只维护 MES 页面、业务 API、领域类型与制造执行规则。认证、租户、菜单、权限、布局、路由、公共组件、Store 和 Supabase 公共客户端由 [`art-supabase-pro`](https://gitee.com/art-si/art-supabase-pro) 统一提供；物料、设备、人员、生产组织、工作中心与工艺路线等基础身份由 MDM 及其权威来源提供。

## 当前状态

MES 已接入工单、排程、现场任务、生产报工、报工审核与制造执行工作台。已下达工单可进入 WMS 领料申请；已审核的完工实绩可进入 WMS 生产入库。库存变动由 WMS 过账，MES 页面不直接修改库存余额。

## 目标执行闭环

```text
生产订单
  → 资源约束与排程
  → 任务派工
  → 开工 / 投料 / 报工
  → 过程检验与异常处置
  → 完工与成品入库
  → 批次 / 序列号全过程追溯
```

## 工单与工序任务列表口径

- 「当前范围」为符合当前筛选的总记录数；「本页待处理 / 待排产」及「本页已下达 / 已排产」只统计当前表格已接受的页记录，随翻页更新。
- 初始化、读取中或读取失败时，概览显示未知值；成功读取的空列表才显示 0。基础资料加载失败可在页内重新加载，列表读取失败沿用表格重试。
- 导出读取完整筛选结果并保留既有导出上限。工序任务导出固定使用点击时的工作中心或车间范围，期间切换导航不会混入另一个范围；当前表格和概览仍显示最新选择。

## WMS 衔接前置条件

- MDM 中启用生产物料、工单组织及适用的 BOM / 工艺资料；需要项目归属时，工单与库存批次使用同一项目和施工号。
- 工单已下达后，领料申请可选择所属组织一致、业务范围包含「拣货」且仓库类型匹配的 WMS 仓库。领料申请审核后才允许分批领料过账。
- 生产入库需先审核报工，入库累计量不得超过已审核完工量；成品、项目及施工号由服务端复核。

## 排包与工单下达契约

- MDM 单据类型以 `packing_enabled` 和 `packing_thickness_field_key` 配置是否需要排包及板厚参数来源。创建工单时保存配置快照；PP20 板材加工已启用。工单数量默认随生产单明细面积汇总，允许手动覆盖。
- 在 MDM主数据 → 单据类型中，先开启「需要排包」，再维护专用字段并指定数字型板厚字段；未开启的类型在生产工单中只显示通用字段。`mes_work_order_references` 按租户和生产工单菜单一次返回类型及排包配置，具备工单查看或新增权限的用户无需单据类型管理权限即可读取所需配置。
- 下达前通过 `mes_work_order_release_warnings` 返回施工号为空和 BOM 原料缺口提醒。施工号允许选填；WMS 自动预留只预留可用库存，缺口不阻止工单下达。
- 排包规则可按板材类型与板厚分别配置。同区域始终是单包约束，`same_number` 控制是否还要求同编号；默认聚合顺序为区域、编号、宽度、长度。
- 包装参数的轴线取明细编号，厚度取工单类型专用板厚。关闭同编号约束后的混编号包显示全部编号。`mes_save_packing_plan_v2` 在数据库校验租户、规则、单包块数、堆叠、重量、长度、区域及编号，并保存所用规则 ID 以便重新打开时恢复选择。
- 包号按生产工单独立生成 `PK-0001`、`PK-0002`，续排与拆包沿用本工单内最大流水，不把工单号拼入包号。业务唯一性由 `(tenant_id, work_order_id, pack_no)` 保证；不同工单允许同名包号，同一工单内禁止重复。跨工单引用、WMS 入库和追溯继续使用包的 `id`，不可只用包号定位。`tests/integration/mes-packing-order-identity.sql` 在回滚事务中验证真实保存 RPC、重复包约束及租户范围，单元与浏览器回归覆盖自动排包、续排、拆包和保存重试。

2026-10-27 已直接更新排包唯一约束及保存校验。结构变更前备份、事务回滚验证和变更后真实 RPC 验证均完成，已有 52 条包记录保持不变；平台全部/指定租户、普通用户本租户及伪造请求头场景通过，安全顾问未新增告警。恢复资料保存在 Git 忽略的 `.artifacts/packing-work-order-identity/before.json`。

- `mes_set_packing_publication` 负责发布与重排包。发布后工单编辑和板材明细、包、包明细修改均由服务端拦截；重排包保留已有包并恢复编辑。发布和重排包分别使用 `MesPacking:Publish`、`MesPacking:Repack` 权限。
- 历史已保存但尚未绑定规则的排包单，需选择适用规则并再次保存后才能发布。
- 排包工作台支持选中整包的 A4 表单打印与自定义尺寸的合格证标签打印。标签默认 100 × 150 mm，可修改宽、高，宽度最大 105 mm；预览与实际打印同步适配纸张，内容缩放保留完整字段，打印机驱动须使用同尺寸纸张。勾选任一明细会带出该包全部板材，标签保留原包序号，超过八条明细生成续页。未保存调整不可打印；执行标准、板型、颜色、质检员与生产日期仅用于本次打印，不写回工单或代替质检判定。
- 打印入口使用 `MesPacking:Print`，位于排包单菜单下。2026-10-22 已通过直接数据库事务验证并注册该权限，初始化授予当时已有 `MesPacking:View` 的三个角色；后续由角色权限管理单独分配。原菜单及角色授权备份保存在 Git 忽略的 `.artifacts/packing-print/permission-backup.json`。业务读取沿用现有 RLS，不新增写接口或更改租户策略；整包解析、续页和失效/跨租户引用拒绝由 `tests/unit/packing-print.test.ts` 覆盖。
- 标签的“区域/编号”显示整包包含的区域与明细编号组合（如 `B区/2轴-1`）；“产品名称”与生产工单列表的“物料描述”共用同一读取和回退逻辑。左侧工单支持双击或 Alt+Enter 打开已有工单详情，保留 `MesWorkOrder:View` 权限和只读模式。

2026-09-29 的数据库事务回滚验证覆盖了空施工号与缺料提醒后仍可下达、按板厚保存规则且拒绝重复配置、参数忽略客户端传入的轴线与厚度、不同编号拒绝混包且有效方案可保存、发布后拒绝包/参数/方案修改，以及重排包恢复编辑。排包规则与选中明细自动拆包由 `tests/unit/packing-plan.test.ts` 验证。

## 独立运行

环境要求：Node.js `>= 22.0.0`、pnpm `>= 11.9.0`。

```powershell
pnpm install
pnpm dev
```

默认访问 `http://localhost:3019`。

```powershell
pnpm check
pnpm build
pnpm preview
```

生产构建输出到 `docs/`，默认公共路径为 `/art-supabase-mes/`，可作为 Pages 发布目录。

## 与主仓协作

MES 业务修改在本仓提交并推送，随后在主仓更新 `modules/art-supabase-mes` 子模块指针。跨模块数据通过用途明确、字段最小化、租户隔离的 API/RPC 契约读取；本仓不直接导入 MDM、WMS 或其他业务仓源码。

## 安全原则

- 普通用户只能访问当前租户及授权生产范围内的数据。
- 派工、开工、报工、质检判定、完工和撤销等动作必须拆分权限并由服务端校验。
- 关键状态、数量、人员、设备、批次和时间变化必须保留可追溯事件，不通过直接改状态绕过流程。
- 页面可见不代表后端授权，数据库 RLS、RPC 与领域状态机是最终安全边界。
