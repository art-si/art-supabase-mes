## 项目定位

Art Supabase MES 是 Art Supabase Pro 的制造执行业务应用，目标是把生产标准、计划排程、现场任务、人员设备实绩、质量结果和物料批次串成可执行、可反馈、可追溯的生产闭环。

本仓只维护 MES 页面、业务 API、领域类型与制造执行规则。认证、租户、菜单、权限、布局、路由、公共组件、Store 和 Supabase 公共客户端由 [`art-supabase-pro`](https://gitee.com/wangyanghub/art-supabase-pro) 统一提供；物料、设备、人员、生产组织、工作中心与工艺路线等基础身份由 MDM 及其权威来源提供。

## 当前状态

MES 已接入工单、排程、现场任务、生产报工、报工审核与制造执行工作台。已下达工单可进入 WMS 领料申请；已审核的完工实绩可进入 WMS 生产入库。库存变动由 WMS 过账，MES 页面不直接修改库存余额。

| 建设领域 | 当前状态 | 目标能力                                      |
| -------- | -------- | --------------------------------------------- |
| 应用底座 | 已完成   | 独立运行、平台装载、统一主题导航与角色访问    |
| 生产标准 | 已接入 MDM | 工艺路线、工序版本、工作中心等基础资料     |
| 计划排程 | 已接入     | 工单、排程与任务下达                       |
| 现场执行 | 部分完成   | 派工、报工、审核及与 WMS 的领料和完工入库 |
| 质量追溯 | 部分完成   | 检验与缺陷页面已接入；跨系统全程追溯待完善 |

## 目标执行闭环

```text
生产订单
  → 资源约束与排程
  → 任务派工
  → 开工 / 投料 / 报工
  → 过程检验与异常处置
  → 完工与成品入库
  → 批次 / 序列号全过程追溯
```

## WMS 衔接前置条件

- MDM 中启用生产物料、工单组织及适用的 BOM / 工艺资料；需要项目归属时，工单与库存批次使用同一项目和施工号。
- 工单已下达后，领料申请可选择所属组织一致、业务范围包含「拣货」且仓库类型匹配的 WMS 仓库。领料申请审核后才允许分批领料过账。
- 生产入库需先审核报工，入库累计量不得超过已审核完工量；成品、项目及施工号由服务端复核。

## 后续建设重点

1. 补全现场投料、退料、设备采集和质量事件的稳定执行契约。
2. 将 WMS 领料、退料及完工入库的库存流水关联到完整工序履历。
3. 基于真实执行事件完善进度、达成率、质量与资源绩效分析。

## 独立运行

环境要求：Node.js `>= 22.0.0`、pnpm `>= 11.9.0`。

```powershell
pnpm install
pnpm dev
```

默认访问 `http://localhost:3019`。

```powershell
pnpm check
pnpm build
pnpm preview
```

生产构建输出到 `docs/`，默认公共路径为 `/art-supabase-mes/`，可作为 Pages 发布目录。

## 与主仓协作

MES 业务修改在本仓提交并推送，随后在主仓更新 `modules/art-supabase-mes` 子模块指针。跨模块数据通过用途明确、字段最小化、租户隔离的 API/RPC 契约读取；本仓不直接导入 MDM、WMS 或其他业务仓源码。

## 安全原则

- 普通用户只能访问当前租户及授权生产范围内的数据。
- 派工、开工、报工、质检判定、完工和撤销等动作必须拆分权限并由服务端校验。
- 关键状态、数量、人员、设备、批次和时间变化必须保留可追溯事件，不通过直接改状态绕过流程。
- 页面可见不代表后端授权，数据库 RLS、RPC 与领域状态机是最终安全边界。
